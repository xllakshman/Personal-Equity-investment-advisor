For engineering

Handoff notes

What this mock implies for the build. Paste this alongside the screens when you start the architecture.

Stack shape

FRONTEND

React + TypeScript, Vite, TanStack Query for server state, Zod schemas shared with the API. No global store — the builder form is one reducer.

API

TypeScript on Node (Fastify or Hono). Analysis runs are queued jobs, not request-scoped — the UI polls or subscribes, because a frontier run takes 40–90s.

DATA

Postgres with row-level security. Object storage for generated PDFs, keyed by report id, served via signed URLs.

LLM LAYER

One provider-agnostic adapter. The prompt lives server-side only, loaded by version id, and the version id is stamped on every report row.

Non-negotiables

Quota is enforced server-side, twice — once when the job is accepted, once before the provider call, because a queued job can outlive the allowance that authorised it.

The risk/CAGR conflict check is a server rule, not a UI nicety. The client mirrors it for immediacy only.

FX is display-only — store every amount in its native currency with the instrument, convert at render, and never round-trip a converted number back into storage.

The prompt never leaves the server. Refusals are a fixed server-side string, not a model behaviour you hope holds.

Reports are immutable once saved. Refinements append; they never rewrite the original verdict, so a user can always see what they acted on.
